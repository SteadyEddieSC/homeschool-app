# v10.39 — Modularization and Offline Regression Foundation

## Goal

Reduce release-builder coupling without changing product behavior, while proving that Beaufort Learning Harbor remains usable after the initial document load with network access blocked.

## Scope

- Extract a reusable offline/runtime contract module from release-specific builder logic.
- Expose a browser runtime ledger for same-origin, embedded, and blocked external requests.
- Add a small offline-readiness status surface without changing role navigation or learner workflows.
- Add explicit browser tests that continue core student and adult workflows after network access is disabled.
- Add screenshot-comparison baselines for selected high-risk learner and adult-role routes.
- Preserve deterministic single-file output, role boundaries, reward boundaries, import/export schemas, and all existing v10.38 behavior.
- Publish an exact v10.39 artifact, checksum, and CI artifact.

## Boundaries

- No broad visual redesign.
- No feature removals.
- No cloud account, database, API, telemetry, service worker, or external calendar dependency.
- No role-policy, learner-route, reward, attendance, mastery, portfolio, or source-record behavior changes.
- No cross-project or L2G changes.

## Acceptance criteria

- Offline/runtime package normalization is deterministic and rejects unsupported or dangerous inputs.
- Browser runtime records same-origin and embedded requests and blocks external fetch/XHR/beacon attempts before network dispatch.
- Student learning routes and the Family/Co-op Planner remain functional after the browser context is switched offline following initial load.
- High-risk visual baselines compare within an explicit pixel-difference budget on desktop Chromium.
- Desktop, touch-tablet, and Pixel 7 suites remain green.
- The release artifact hash, byte count, markers, package version, and active pointer are exact.
