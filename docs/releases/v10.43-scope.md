# v10.43 — Lesson Pack Controlled Apply v1

## Goal

Add a reviewed, reversible draft-to-live overlay workflow for Lesson Pack Editor drafts while preserving original source content, existing curriculum, role boundaries, offline behavior, and all reward and learner-record boundaries.

## Scope

- Build deterministically from merged v10.42.
- Add a schema-1 controlled-apply operations module.
- Keep Lesson Pack drafts immutable during apply and rollback.
- Require explicit adult review before apply.
- Support selective approval of objective, individual sections, practice prompts, lab/project prompts, no-equipment path, and media plan.
- Add before/after comparison against the selected target destination.
- Store applied content as browser-local overlays rather than rewriting target-screen source content.
- Add deterministic overlay fingerprints, source-pack references, target week/screen references, reviewer audit notes, and capped audit entries.
- Support rollback without deleting the source draft or prior audit evidence, including restoration of the prior active destination state.
- Keep media provenance/license review and no-equipment readiness visible during approval.
- Require an original/OER/public-domain/nonprofit/government-use attestation.
- Render active student-safe overlays at their target destinations while hiding adult review notes and controls.
- Preserve Parent/Teacher/Admin management, Director read-only rollup, and Student denial of authoring/apply controls.
- Add Node and desktop/touch-tablet/Pixel 7 browser coverage.
- Advance the maintained roadmap through v10.52.

## Boundaries

- No destructive rewrite of original curriculum, Lesson Pack drafts, assignments, progress, or target-screen source content.
- No automatic completion, XP, coins, grades, attendance, mastery, portfolio approval, or record mutation.
- No automatic application based only on draft status.
- No proprietary curriculum-copy workflow or silent copyright attestation.
- No external calendar, cloud account, API, database, telemetry, service worker, network dependency, cross-project infrastructure, or L2G changes.
- Preliminary curriculum records remain planning input only and cannot become live overlays without exact adult review.

## Acceptance criteria

- Controlled-apply plans validate deterministically and fail closed on malformed, unsupported, duplicate, dangerous, or polluted inputs.
- Apply requires a ready Lesson Pack, at least one selected student-facing component, explicit content-rights attestation, and an audit note.
- Media selection requires explicit provenance/license review; no-equipment selection preserves directions and evidence expectations.
- Apply creates a new overlay and audit entry without modifying the source draft or existing target content.
- Reapplying an identical active fingerprint does not create a silent duplicate.
- Rollback deactivates the overlay, preserves source and audit evidence, restores prior active state, and is itself audited.
- Student-safe destination rendering excludes adult notes, rights attestations, reviewer identity details, audit metadata, and rollback controls.
- Existing privacy, offline, role-policy, route-resolver, console/page-error, bounded-mutation, accessibility, data, visual, Knowledge Check, Lesson Pack v1, Family Planner v1/v2, hero, dock, and destination gates remain green.
- Exact standalone artifact bytes and SHA-256 match the release manifest and downloadable Actions artifact.
