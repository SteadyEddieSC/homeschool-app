# v10.34.1 — Mobile Destination Stability

## Report

On the public v10.34 Worker, the five-action student dock remained stable, but routed learning pages could visibly blink or change size on mobile. The Biology Learn destination showed its visual-model image and surrounding card alternating between layouts while the page remained open.

## Root cause

The legacy source-media compatibility layer attached a `MutationObserver` to the document. Every observed child mutation scheduled `polish()`. During each pass:

- `buildUnifiedAtlas()` removed and recreated `.blh-source-gallery`.
- `buildVisualModel()` removed and recreated `.blh-visual-model`.

Those removals and insertions were themselves child mutations, so the observer scheduled another pass. This created a self-triggered structural rebuild loop even when the underlying content had not changed.

## Correction

- Existing source-media galleries are now retained and returned rather than removed.
- Existing visual-model sections are now retained and returned rather than removed.
- The release includes `data-destination-stability="v10.34.1"`.
- Static verification rejects either legacy remove-and-rebuild statement.
- Pixel 7 testing holds every student destination open and verifies stable screen identity, stable visual-model identity, stable width, route persistence, target-banner persistence, and preservation of the authoritative dock node.
