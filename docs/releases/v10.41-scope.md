# v10.41 — Learner Route and Assignment Resolver

## Goal

Move learner-track matching, next-assignment selection, completion-aware route choice, direct assignment destination resolution, and safe route fallbacks behind one reusable tested contract without changing current Jordan/Avery route outcomes.

## Scope

- Build deterministically from merged v10.40.
- Add `modules/learner-route-resolver.mjs` with schema-1 validation.
- Normalize learner identity and track aliases while using a deterministic lower-track fallback for incomplete learner records.
- Support existing all-learner, lower/upper track, exact learner ID, `student:`, and `track:` assignment targets.
- Prefer the first unfinished matching assignment; when all matching items are complete, repeat the first matching assignment deterministically.
- Resolve direct assignment destinations through the same learner-applicability and destination-safety contract.
- Use route-kind fallbacks for missing assignments and missing/unavailable destinations; use Home only when the normal route fallback is unavailable.
- Skip malformed, duplicate, unsupported, dangerous, or polluted assignment entries deterministically.
- Expose read-only `window.BLHLearnerRouteResolver` and `window.BLHLearnerRouteRuntime` diagnostics.
- Route existing Learning Path controls, direct assignment buttons, and adult Route QA through the resolver.
- Add Node tests and desktop/touch-tablet/Pixel 7 browser coverage.
- Update the maintained roadmap through v10.50.

## Boundaries

- No broad visual redesign.
- No intended change to the existing Jordan/Avery Learn, Practice, Quiz/Test, Proof, or Feedback outcomes.
- No route-only XP, coins, grades, automatic completion, attendance, mastery, portfolio approval, or source-record mutation.
- Existing local route completion markers remain planning/QA markers only.
- Formal quiz/test routing remains separate from adult-reviewed proof.
- No final curriculum pacing generated from preliminary curriculum sources.
- No cloud account, API, database, telemetry, service worker, external calendar dependency, cross-project infrastructure, or L2G changes.

## Acceptance criteria

- One module owns learner normalization, assignment applicability, completion keys, next-item selection, direct assignment destination resolution, and route fallbacks.
- Existing upper/lower synthetic route matrices remain parity-clean.
- Incomplete learner records use the lower route without mutating application state.
- Missing/malformed assignments and missing destinations fail closed to documented route fallbacks.
- Direct assignment requests cannot widen work to the wrong learner.
- Resolver results and diagnostics are defensive and read-only.
- Existing role-policy, privacy, offline, console/page-error, bounded-mutation, accessibility, route, data, visual, Knowledge Check, Lesson Pack, Family Planner, hero, dock, and destination gates remain green.
- Exact standalone artifact bytes and SHA-256 match the release manifest and downloadable Actions artifact.
