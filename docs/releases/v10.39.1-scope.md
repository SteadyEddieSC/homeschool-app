# v10.39.1 — Console and Observer Stability Hotfix

## Goal

Stop the continuous desktop console failure reported against the public Worker and ensure the loaded single-file application reaches a quiet, bounded DOM state.

## Evidence

The production console repeatedly reported `ReferenceError: VERSION is not defined` from the retained learning-path `updateTitleBits()` function. That exception was emitted through a legacy MutationObserver callback as `BLH v10.18 apply skipped` and recurred whenever other versioned layers changed the DOM.

Investigation proceeded in bounded stages:

1. Restoring the missing `VERSION` binding removed the uncaught exception but did not address the underlying repeated work.
2. Retiring nine obsolete pre-v10.24 body-wide observer registrations retained their initial render pass, but browser CI still measured roughly 1,500 mutation records in a two-second steady-state window.
3. Retiring fifteen legacy startup polling loops reduced the browser-CI measurement to approximately 625 records per two seconds.
4. The enhanced mutation report attributed about 490 of those records to the v10.29 media cleanup repeatedly adding classes already present on embedded images. The final candidate makes those image and hidden-tool class operations idempotent.

This evidence is from the deterministic release artifact and automated Chromium runs. Public production is not inferred from a branch preview and must be reconciled separately after merge.

## Scope

- Build v10.39.1 deterministically from v10.39.
- Add the missing release-version binding to the affected learning-path block.
- Reconcile application, Knowledge Check, Lesson Pack, and Family Planner portable product versions to `10.39.1` while preserving schema version `1`.
- Retire the first nine retained legacy body-wide MutationObserver registrations after their initial render pass.
- Retire fifteen legacy startup polling loops after their initial render pass while preserving event handlers and current observers.
- Make retained media-manager class cleanup idempotent.
- Preserve the historical v10.39 offline-runtime release-note identity.
- Add static release-integrity checks for the version binding, retirement counts, and media class guards.
- Add desktop, touch-tablet, and Pixel 7 browser coverage for page errors, legacy console warnings, and bounded post-load mutations.
- Publish an exact standalone artifact and checksum.

## Boundaries

- No v10.40 role-policy or app-shell work.
- No broad visual redesign or feature removal.
- No route, role, reward, completion, attendance, mastery, portfolio, data-schema, or source-record behavior changes.
- No cloud, API, database, telemetry, service worker, or external calendar dependency.
- No cross-project or L2G changes.

## Acceptance criteria

- No uncaught `VERSION is not defined` error.
- No recurring `BLH v10.18 apply skipped` warning.
- No more than 500 mutation records during the two-second post-load stability window.
- All portable export product versions report `10.39.1` while schemas remain `1`.
- Existing desktop, tablet, Pixel 7, route, role, accessibility, offline-runtime, visual, data, Knowledge Check, Lesson Pack, Family Planner, hero, dock, and destination-stability gates remain green.
- Exact manifest bytes and SHA-256 match the downloadable artifact.
